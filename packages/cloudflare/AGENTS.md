# packages/cloudflare

The Cloudflare Worker: `src/index.ts` (entry; builds a handler per `env` and maps `ConfigError` to a 500), `src/platform.ts` (`CF-Connecting-IP` and `request.cf` to `PlatformInfo`), `src/modules.ts` (modules built into the worker).

- **Types.** `worker-configuration.d.ts` is generated by `npm run types` from `wrangler.jsonc` (runtime types plus `Env`). Regenerate it after changing `wrangler.jsonc` or `compatibility_date`; CI runs `npm run types:check`. Don't edit it by hand. The project uses `moduleResolution: Bundler` because Wrangler bundles the worker and the generated types assume it; every other strict setting is inherited.
- **Tests** run inside workerd through `@cloudflare/vitest-plugin` (`vitest.config.ts`). Call the worker with `exports.default.fetch(new Request(...))` from `cloudflare:workers`. Cover IPv4 and IPv6 clients where the client IP matters. `platformInfo` is tested directly with plain objects, since `request.cf` can't be set on test requests.
- **`compatibility_date`** must not be newer than the workerd bundled with the installed `wrangler` and `@cloudflare/vitest-plugin`; the test pool fails to start otherwise. Bump it with those packages.
- **Configuration** lives in `vars` in `wrangler.jsonc`, as strings, with every setting listed so deployers see them. Don't add secrets to `vars`; nothing in SharedID Edge needs one today.
- **Deploying** (`npm run deploy`) needs a Cloudflare account; never run it from pull-request CI. `npm run build` is a dry-run bundle (`wrangler deploy --dry-run`) for checking size and that it bundles.
- **Adding a module:** import it in `src/modules.ts`; it runs only when listed in `SID_MODULES`. Add a worker test when it reads Cloudflare-specific data (`request.cf` fields go through `platformInfo` and core's `locationInfo`; extend `PlatformInfo` in core rather than reading `request.cf` in the module, so modules stay portable).
