# packages/adapters/cloudflare

User documentation is in [README.md](README.md); keep it in step with behaviour changes. Read [`../AGENTS.md`](../AGENTS.md) first: the rules for every adapter.

The Cloudflare Worker: `src/index.ts` (entry; builds a handler per `env` and maps `ConfigError` to a 500), `src/platform.ts` (`CF-Connecting-IP` and `request.cf` to `PlatformInfo`). The modules come from `@sharedid-edge/modules`.

- **Types.** `worker-configuration.d.ts` is generated by `npm run types` from `wrangler.jsonc` (runtime types plus `Env`). Regenerate it after changing `wrangler.jsonc` or `compatibility_date`; CI runs `npm run types:check`. Don't edit it by hand. The project uses `moduleResolution: Bundler` because Wrangler bundles the worker and the generated types assume it; every other strict setting is inherited.
- **Tests** run inside workerd through `@cloudflare/vitest-plugin` (`vitest.config.ts`). Call the worker with `exports.default.fetch(new Request(...))` from `cloudflare:workers`. Cover IPv4 and IPv6 clients where the client IP matters. `platformInfo` and `botManagementTraffic` are tested directly with plain objects; a request built with `new Request(url, { cf })` passes `request.cf` through `exports.default.fetch`.
- **`compatibility_date`** must not be newer than the workerd bundled with the installed `wrangler` and `@cloudflare/vitest-plugin`; the test pool fails to start otherwise. Bump it with those packages.
- **Configuration** lives in `vars` in `wrangler.jsonc`, as strings, with every setting listed so deployers see them. Don't add secrets to `vars`; nothing in SharedID Edge needs one today.
- **Live test environments:** `env.e2e` and `env.conformance` in `wrangler.jsonc` are this project's own [live tests](README.md#live-tests) on `sharedid.dev`. Wrangler doesn't inherit `vars`, so they list every setting; keep them in step when adding one (`npm run types` covers the types). Only `.github/workflows/e2e-cloudflare.yml` deploys them, never pull-request CI.
- **Deploying** (`npm run deploy`) needs a Cloudflare account. `npm run build` is a dry-run bundle (`wrangler deploy --dry-run`) for checking size and that it bundles.
- **New platform data:** `request.cf` fields go through `platformInfo` and core's `locationInfo`, never read by a module. Add a worker test when a module depends on Cloudflare-specific data.
