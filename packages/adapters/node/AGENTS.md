# packages/adapters/node

User documentation is in [README.md](README.md); keep it in step with behaviour changes. Read [`../AGENTS.md`](../AGENTS.md) first: the rules for every adapter.

A Node.js HTTP server around the core handler (`src/index.ts`, `createNodeServer`) and its CLI (`src/cli.ts`, configured by environment variables). Used for local development, self-hosting behind a reverse proxy, and as a conformance target.

- Converts `IncomingMessage` to `Request` and the `Response` back (each `Set-Cookie` its own header), and fills `PlatformInfo`. The conversion (`toWebRequest`, `sendWebResponse`, `utf8`) is exported and reused by `@sharedid-edge/gcp-functions`; changing it changes that adapter too. The CLI builds in `builtInModules` from `@sharedid-edge/modules`.
- The client IP is the socket address unless `trustProxy` is set; only then is the first `X-Forwarded-For` entry used (or, with `clientIpHeader`/`SID_CLIENT_IP_HEADER`, the proxy's own client-IP header instead, read by `clientIpFromHeader`: a bare IP, or CloudFront's `ip:port` through core's `parseViewerAddress`; missing or invalid gives no client IP, never a fallback to `X-Forwarded-For`; setting it without `trustProxy` is a `ConfigError`), and the location read from Cloudflare's visitor location headers (`cf-ipcountry`, `cf-region-code`, `cf-ipcity`, …), or from the headers `SID_LOCATION_HEADERS` names (`locationHeaders`), through core's `locationWithEU`, so the country also sets `isEU`, which decides GDPR's scope. Keep that the default: the headers are client-controlled otherwise. This is the one trust setting the adapter rules allow for. Reading the headers is core's `forwardedPlatformInfo` (with `clientIpFromHeader` and `utf8Header`, re-exported here as `clientIpFromHeader` and `utf8`); the adapter adds only the fallback to the socket address when `X-Forwarded-For` is empty.
- **Trusted upstream** (`SID_UPSTREAM_SECRETS`, the `upstream` option): core's `withTrustedUpstream` wraps the handler, as on the Worker and Lambda. The CLI reads it with `trustedUpstreamFromEnv(env, { trustProxy })`, and passes `SID_CLIENT_IP_HEADER` and `SID_LOCATION_HEADERS` to `createNodeServer` only with `SID_TRUST_PROXY`.
- `test/proxy.test.ts` runs the server behind a local stand-in CDN (`node:http`) that overwrites its client-IP and country headers and appends to `X-Forwarded-For`, as the sales-house setup does; it starts and closes its own servers, so keep such tests out of `server.test.ts`, whose `afterEach` closes the one server it started.
- `publicOrigin` sets the request URL's origin; without it, it's `http://<Host header>`. Behind TLS termination it's optional: a public `Host` over http already gets `Secure` cookies (core decides, see [Secure cookies](../../../docs/configuration.md#secure-cookies)). It matters when the proxy doesn't pass the public `Host`.
- Tests (`test/server.test.ts`, `test/proxy.test.ts`) start a real server on a random port and use `fetch`.
