# packages/core

The platform-neutral implementation: `createHandler` (routes, ID choice, cookies, responses), `resolveConfig`, consent (`consent.ts`, `tcf.ts`) the module interface (`modules.ts`) and the shared traffic signal (`traffic.ts`: report validation, the most-cautious-wins merge, and `SID_SKIP_BOTS`). Published as `@sharedid-edge/core`; adapters and modules depend on its public API in `src/index.ts`.

- **No platform APIs.** The project compiles with `lib: ["ES2023", "WebWorker"]` and no Node or DOM types: only `Request`, `Response`, `Headers`, `URL`, `crypto.randomUUID`, `TextEncoder` and timers. Anything platform-specific (the client IP, `request.cf`) comes in through `PlatformInfo` from the adapter. Adapters validate location data with `locationInfo` (`location.ts`), so every platform drops the same bad values, and derive `isEU` from a country with `EU_COUNTRY_CODES` (the 27 member states, the meaning of Cloudflare's `isEUCountry`; update it if EU membership changes).
- **No runtime dependencies.** It's bundled into every worker. A full TCF decoder is deliberately not used; `tcf.ts` reads only what's needed.
- **Public API.** Everything exported from `src/index.ts` is public. Changing an exported type or signature is a breaking change for adapters and module authors: check `consumer-types/fixture/consumer.ts` still compiles (`npm run consumer-types`) and update it to cover new exports. `isolatedDeclarations` is on, so exports need explicit types.
- **Configuration.** New settings go in `SharedIdEdgeConfig`, `DEFAULT_CONFIG` and `resolveConfig` (with validation that throws `ConfigError`), the table in `resolveConfig`'s JSDoc, `spec/SPEC.md`, the README's configuration reference, and `packages/adapters/cloudflare/wrangler.jsonc` `vars` (then `npm run types -w @sharedid-edge/cloudflare`).
- **Tests** are in `test/` (Vitest, Node environment): `unit.test.ts` for the building blocks, `handler.test.ts` for behaviour through the handler. `test/helpers.ts` has `tcString(purposes, { publisher, vendors })` and `publisherTc(purposes)` to build TC strings and `setCookies(response)` to parse cookies. Use a fixed clock and ID generator (`createHandler({ now, mintId })`) for deterministic assertions.

## Modules

Core defines the module interface (`EdgeModule`, `ModuleContext`, `defineModule`, `runModules` in `modules.ts`) and runs modules, but never depends on one. Modules run on `/v1`, and those whose `routes` include `sync` also on `/sync` (chosen with `SID_SYNC_MODULES`), where `syncResponse` in `handler.ts` applies only their cookies and reports statuses in `X-SharedID-Modules`; keep `/sync`'s status, body and other headers unchanged for Prebid.js. How to write a module, and the rules for them, are in [`../modules/AGENTS.md`](../modules/AGENTS.md); vendor modules add [`../vendor-modules/AGENTS.md`](../vendor-modules/AGENTS.md). Changing the interface is a public API change for every module.
