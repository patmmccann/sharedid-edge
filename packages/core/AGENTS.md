# packages/core

The platform-neutral implementation: `createHandler` (routes, ID choice, cookies, responses), `resolveConfig`, consent (`consent.ts`, `tcf.ts`) the module interface (`modules.ts`) and the shared traffic signal (`traffic.ts`: report validation, the most-cautious-wins merge, and `SID_SKIP_BOTS`). Published as `@sharedid-edge/core`; adapters and modules depend on its public API in `src/index.ts`.

- **No platform APIs.** The project compiles with `lib: ["ES2023", "WebWorker"]` and no Node or DOM types: only `Request`, `Response`, `Headers`, `URL`, `crypto.randomUUID`, `TextEncoder` and timers. Anything platform-specific (the client IP, `request.cf`) comes in through `PlatformInfo` from the adapter. Adapters validate location data with `locationInfo` (`location.ts`), so every platform drops the same bad values, and derive `isEU` from a country with `EU_COUNTRY_CODES` (the 27 member states, the meaning of Cloudflare's `isEUCountry`; update it if EU membership changes).
- **Adapter plumbing** that every adapter would otherwise copy lives in `adapter.ts`: `splitHeaders` (each `Set-Cookie` kept separate), `logRequestFailure` (logs the error's type, never its message), `handlerOrMisconfigured` (a `ConfigError` gives a handler that answers with a 500), `publicOriginFromEnv`, `headerValue`, `isHeaderName`, `parseHeaderMap` and `parseViewerAddress` (CloudFront's `ip:port` client address, used by the Lambda adapter and the Node.js server) (a JSON setting mapping fields to header names, such as `SID_LOCATION_HEADERS`); in `ip.ts`, `parseIp` (an IPv4 or IPv6 address, used to check client IPs and by the `ip` and `ec` modules); and in `location.ts`, `locationWithEU` (`locationInfo` plus `isEU`). Add a helper here when a second adapter needs the same code, and keep it platform-neutral.
- **Several sites** (`hosts.ts`): `settingsFromEnv` gives adapters `{ config, hosts }` from `SID_HOSTS`, and `createHandler` picks the configuration by the request's hostname (`hostKey`), with `hostConfig` for a platform's per-host settings. Every adapter builds its handler through `settingsFromEnv`, so `SID_HOSTS` works the same everywhere.
- **Trusted upstream** (`upstream.ts`): an endpoint behind a publisher's CDN. `trustedUpstreamFromEnv` reads `SID_UPSTREAM_SECRETS` and the headers; `withTrustedUpstream` wraps an adapter's handler (outside `createHandler`, so bundles that don't use it, like the Snippet, don't carry it): a constant-time secret check (403 otherwise), `forwardedPlatformInfo` in place of the platform's data, the forwarded host as the URL's host, and the auth header removed. Adapters without it refuse `SID_UPSTREAM_*` with `refuseTrustedUpstream`, kept out of `settingsFromEnv` so the Snippet, close to its 32 KB limit, doesn't carry it (its build refuses the settings itself). For the same reason the check that none of them is set per host in `SID_HOSTS` is in `upstream.ts` (`trustedUpstreamFromEnv` and `refuseTrustedUpstream` both run it), not in `hostOverrides`. `forwardedPlatformInfo`, `clientIpFromHeader` and `utf8Header` are shared with the Node.js server's `trustProxy`. Errors never show a secret.
- **Request limits and the rate limiter** (`handler.ts`): `/sync` and `/v1` answer a path and query over `MAX_URL_BYTES` with a `414` and a `Cookie` header over `MAX_COOKIE_BYTES` with a `431`, then ask the optional `rateLimit` (`429` when it refuses, and through when it fails), all before consent, the ID or modules. Opt-out and opt-in are never refused. The rate-limit check sits behind `globalThis.__SID_NO_RATE_LIMIT__` (`NO_RATE_LIMIT`), defined true by every build that never passes `rateLimit`, so it compiles away there; core keeps no counters.
- **No request state outside a request.** A handler serves many requests: adapters cache it per settings (`cachedByEnv`), and the Fastly adapter's reusable-sandbox build keeps the whole instance between visitors. Nothing derived from a request may be kept at module level or in the handler's closures; caches keyed by configuration (the per-host handlers, `cachedByEnv`) are fine. `resolveConfig` deep-freezes `moduleConfig` and `moduleSecrets`, since modules get them by reference.
- **No runtime dependencies.** It's bundled into every worker. A full TCF decoder is deliberately not used; `tcf.ts` reads only what's needed.
- **The TCF decoder can be left out** (`NO_TCF` in `consent.ts`): builds with `--no-tcf` (the Snippet's, `scripts/bundle-adapter.mjs`'s) define `globalThis.__SID_NO_TCF__` true, so `readConsent` never calls `decodeTcf` and `tcf.ts` compiles away; every other build defines it false or leaves it unset. A TC string then denies storage and precise location as an unreadable one does (reason `tcf: TC string not decoded (build without TCF)`). Keep it fail-closed: nothing may treat an undecoded TC string as consent. It's a build flag rather than a consent provider: the TC string's decoded consents (`ConsentContext.tcf`) feed the storage decision, precise location and modules' `purposes`, which a provider's granted or denied signal can't carry, and every caller of `createHandler` keeps TCF without wiring anything. `decodeTcf` stays exported.
- **Public API.** Everything exported from `src/index.ts` is public. Changing an exported type or signature is a breaking change for adapters and module authors: check `consumer-types/fixture/consumer.ts` still compiles (`npm run consumer-types`) and update it to cover new exports. `isolatedDeclarations` is on, so exports need explicit types.
- **Configuration.** New settings go in `SharedIdEdgeConfig`, `DEFAULT_CONFIG` and `resolveConfig` (with validation that throws `ConfigError`), the table in `resolveConfig`'s JSDoc, `spec/SPEC.md`, the README's configuration reference, and `packages/adapters/cloudflare/wrangler.jsonc` `vars` (then `npm run types -w @sharedid-edge/cloudflare`).
- **Tests** are in `test/` (Vitest, Node environment): `unit.test.ts` for the building blocks, `handler.test.ts` for behaviour through the handler. `test/helpers.ts` has `tcString(purposes, { publisher, vendors })` and `publisherTc(purposes)` to build TC strings and `setCookies(response)` to parse cookies. Use a fixed clock and ID generator (`createHandler({ now, mintId })`) for deterministic assertions.

## Modules

Core defines the module interface (`EdgeModule`, `ModuleContext`, `defineModule`, `runModules` in `modules.ts`) and runs modules, but never depends on one. Modules run on `/v1`, and those whose `routes` include `sync` also on `/sync` (chosen with `SID_SYNC_MODULES`), where `syncResponse` in `handler.ts` applies only their cookies and reports statuses in `X-SharedID-Modules`; keep `/sync`'s status, body and other headers unchanged for Prebid.js. How to write a module, and the rules for them, are in [`../modules/AGENTS.md`](../modules/AGENTS.md); vendor modules add [`../vendor-modules/AGENTS.md`](../vendor-modules/AGENTS.md). Changing the interface is a public API change for every module.

**Consent providers** (`EdgeModule.consent`, `consentSignal` in `modules.ts`; `storageDecisionWith` and `storageDecision` in `consent.ts`): modules in `SID_MODULES` with a `consent` hook give a signal before the storage decision, on `/v1` and `/sync`. A denial (or a hook that throws or returns anything else) denies; a grant only lifts the denial for want of a TC string where GDPR applies; GPC, COPPA and opt-out come first. The spec's [Consent providers](../../spec/SPEC.md#consent-providers) is the contract, meant to carry the non-TCF CMP cookies (`cmp`), GPP opt-outs (`gpp`) and Google Consent Mode. TCF itself stays in core, behind `NO_TCF` (above). **Size:** builds whose module list has no hook define `globalThis.__SID_NO_CONSENT_HOOKS__` (`scripts/bundle-adapter.mjs` without `--module`, the Worker's npm scripts, a Snippet without such a module), so the handler calls `storageDecision` and the provider code compiles away: keep it behind that flag, and keep `storageDecision` the whole decision without providers.

`ModuleResult.eip` is the client IP encrypted per recipient (the `encrypted-ip` module): `google`, and `pbs` keyed by lower-case host name (with an optional port), each `{ value, kid?, stale? }`. Core checks it before using any of the module's output (`checkEncryptedIp`: base64url of 67 to 124 characters, a printable `kid`, nothing else) and returns it as the payload's `eip`, never in `ortb2`; a later module's value for a recipient replaces an earlier one's. Tests in `test/encrypted-ip.test.ts`.

`ModuleResult.stale` is a boolean flag for old or missing reference data. Validate it before applying any output; true adds `ModuleReport.stale: true`, even when the result is otherwise empty, preserving `ok`/`empty` status. Valid last-good output still contributes; errors, timeout and consent skips retain precedence. Downloads, storage reads and freshness policy belong to `@sharedid-edge/data-updates` and the adapter setup, never core or module execution. Unit tests in `test/stale.test.ts` and `conformance/cases/module-data-stale.json` cover the contract.
