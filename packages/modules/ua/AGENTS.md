# packages/modules/ua

User documentation is in [README.md](README.md) (also the npm package page); keep it in step with behaviour changes.

The `ua` module (`@sharedid-edge/module-ua`): User-Agent Client Hints and the `User-Agent` header as the `/v1` payload's OpenRTB 2.6 `ortb2.device` (`sua`, `devicetype`, `os`, `osv`, `make`, `model`, optional `ua`), and the shared traffic signal `device.ext.traffic` for self-identified bots. See the [spec section](../../../spec/SPEC.md#the-ua-module). It follows the module rules in [`../AGENTS.md`](../AGENTS.md).

- **Files:** `src/client-hints.ts` parses the hint headers (RFC 8941 lists, strings and booleans, GREASE); `src/module.ts` maps hints and the parsed `User-Agent` to `device` and applies consent; `src/parse.ts` has the parser interface and the built-in `botParser`; `src/bowser.ts` (the `./bowser` subpath export) has `bowserParser` (Bowser, plus Apple TV and Fire TV as set-top boxes) and `uaModuleWithBowser`, the module in `@sharedid-edge/modules/bowser` (the adapters' Bowser builds and the Node.js server).
- **Runtime dependencies, an exception to the module rules:** [`isbot`](https://github.com/omrilotan/isbot) (Unlicense) is bundled into every adapter; [`bowser`](https://github.com/bowser-js/bowser) (MIT) only in Bowser builds (`@sharedid-edge/modules/bowser`: the Worker's `src/bowser.ts` entry point, aliased in by `bundle:bowser` elsewhere) and the Node.js server. Keep `bowser` out of `src/index.ts`, `src/module.ts` and `@sharedid-edge/modules`, or it lands in every bundle (maintainer decision: off by default, to keep bundles small). It costs about 8 to 8.7 KB gzipped (bundles of 26 to 28 KB with it); CI checks the Bowser builds against the same 32 KB budget, so update the size tables in the README files when it changes. Any new dependency must be permissively licensed (MIT, BSD, Apache-2.0 or public domain), maintained, ESM, web-standard only, and typed under `skipLibCheck: false`; measure its gzipped cost with `npm run build -w @sharedid-edge/cloudflare`.
- **Request headers, not `PlatformInfo`:** the hints and `User-Agent` are sent by the browser, so the module reads them from `request.headers`. The one platform quirk handled here: `User-Agent: Amazon CloudFront` (CloudFront's substitute when the header isn't forwarded) counts as absent.
- **Parsers:** the `parser` setting picks `botParser` (`"isbot"`, the default) or the module's `bowser` parser; a module created without one reports `error` for `"bowser"`. Bowser output is mapped to native OpenRTB `device` fields only (no `device.ext` browser or engine).
- **Hints first,** the parser second. Never send a value browsers freeze (macOS `10.15.7`, `Windows NT 10.0`, Android `10; K`, the `.0.0.0` in reduced Chromium versions).
- **Consent:** `highEntropyDenial` decides; the low-entropy and high-entropy field lists are in the spec, and moving a field between them is a spec change. The traffic signal is always sent (maintainer decision in #5).
- **The traffic signal** is the agreed shape from #5, `{ bot: true, botKind: 'declared', sources: ['ua'] }`, written as `ortb2.device.ext.traffic`, which core reads as the module's report and merges with the others (#58). Moving it to `ModuleResult.traffic` is a possible cleanup. Never write `bot: false`.
- **Settings fail loudly:** `uaSettings` throws on an unknown key, a non-boolean `ua`, or a `parser` other than `"isbot"` and `"bowser"`.
- Tests in `test/ua.test.ts` cover header parsing (GREASE, quoting, malformed values), the device-type mapping, a corpus of real User-Agents (`test/corpus.ts`), consent, the traffic signal and the module through `createHandler`. Conformance cases are in `conformance/cases/module-ua*.json`: `module-ua.json` asserts only what comes from hints and the bot flag; `module-ua-bowser.json` (`"build": ["bowser"]`) runs the Bowser option on every target's Bowser build.
