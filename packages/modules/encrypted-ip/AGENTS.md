# packages/modules/encrypted-ip

User documentation is in [README.md](README.md) (also the npm package page); keep it in step with behaviour changes. The rules for every module are in [`../AGENTS.md`](../AGENTS.md), including [opt-in modules](../AGENTS.md#opt-in-modules).

The `encrypted-ip` module (`@sharedid-edge/module-encrypted-ip`): the client IP encrypted (HPKE, RFC 9180) to each configured recipient's X25519 key, in the payload's `eip`: `google` for Google Publisher Tag's publisher-provided IP, `pbs` by Prebid Server host (experimental, prebid/prebid-server#5106 and prebid/Prebid.js#16281). Its behaviour is specified in [`spec/modules/encrypted-ip.md`](../../../spec/modules/encrypted-ip.md): change it with the code.

- **Opt-in, a project module.** `"optIn": true`; never add it to `builtInModules` (it would grow every bundle), and it isn't in the Snippet build (no schedule or storage for keys there). It's a project module, not a vendor one, because it derives no ID: every value uses a fresh ephemeral key, and only the recipient can read it. Keep it that way: no deterministic encryption, no caching of values per address (which would also keep visitor data between requests).
- **One HPKE implementation for every recipient** (`src/hpke.ts`): base mode, DHKEM(X25519, HKDF-SHA256), HKDF-SHA256, AES-256-GCM only, with Web Crypto only (HKDF's Extract and Expand from HMAC, as `LabeledExtract`/`LabeledExpand` need them apart). A new recipient is a new key and output entry, never a new scheme. Google's format is fixed: empty `info` and `aad`, `enc || ciphertext`, unpadded base64url.
- **The test vectors are the proof.** `test/hpke.test.ts` checks RFC 9180's published vector for exactly this suite (mode 0, KEM 0x0020, KDF 0x0001, AEAD 0x0002, from the CFRG's `test-vectors.json`) and A.1.1's KEM shared secret, with the ephemeral key injected through `seal`'s test-only `ephemeral` option. Copy vectors as published; never regenerate them with this code. `test/receiver.ts` decrypts with Web Crypto's own HKDF, independently of `src/hpke.ts`, for round trips per recipient.
- **Keys never come from the network during a request.** Settings (`key`, `keyFetched`) or scheduled snapshots (`createEncryptedIpModule({ keys })`, fed by `@sharedid-edge/data-updates/encrypted-ip`). Only public keys; refuse a JWK with `d`. Staleness is per recipient: 24 hours (`IP_KEY_MAX_AGE_MS`), Google's rotation overlap; a missing key leaves that recipient out and reports `stale`, never `error`.
- **Consent is the `ip` module's** (`preciseLocationDenial`) plus every storage denial that isn't TCF's own (opt-out cookie, consent providers). Identical for every recipient. Changing it is a behaviour change: spec, conformance (`conformance/cases/module-encrypted-ip*.json`), tests, README.
- **Output only in `eip`,** never `ortb2`: core checks it (`checkEncryptedIp` in core's `modules.ts`). Pages must hand each value to its recipient alone.
- **Runtimes:** X25519 in Web Crypto is required. Akamai EdgeWorkers and Fastly Compute lack it; their conformance targets list the encrypting cases (`encryptedIpCases` in `conformance/src/targets.ts`), and the Akamai stand-in offers only the `subtle` methods EdgeWorkers documents. If either gains X25519, the runner fails until the limitation is removed.
- Never log, store or hash the address. Error messages name settings, never key or address values.
