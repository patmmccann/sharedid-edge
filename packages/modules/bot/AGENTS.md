# packages/modules/bot

User documentation is in [README.md](README.md) (also the npm package page); keep it in step with behaviour changes.

The `bot` module (`@sharedid-edge/module-bot`): bot and staff-traffic reports for the shared traffic signal, `ortb2.device.ext.traffic`. See the [spec section](../../../spec/modules/bot.md) and the [traffic signal](../../../spec/SPEC.md#traffic-signal) rules. It follows the module rules in [`../AGENTS.md`](../AGENTS.md).

- **Report with `traffic`, never `ortb2`.** Core merges every report and writes `ortb2.device.ext.traffic` itself; it sets `sources` too.
- **No platform verdicts here.** The platform's verdict (Cloudflare Bot Management) enters through `PlatformInfo.traffic`, filled by the adapter, and core merges it as source `platform`. Repeating it here would count it twice and tie the output to this module. A platform *fact* the module judges itself is different: `ja4Mismatch` reads `PlatformInfo.ja4` (the JA4 TLS fingerprint, which adapters fill only from the platform, never from a request header) and compares it with the user agent.
- **Runs on `/v1` and `/sync`** (`routes`). Its only output is a traffic report, which on `/sync` counts towards `SID_SKIP_BOTS`; don't add payload or cookies, which `/sync` would drop or set on every pixel call.
- **No crawler list.** Declared crawlers are the `ua` module's job (`botKind: declared`), including its scheduled list updates. This module only has heuristics (`likely`) and the internal marker, so it reads no reference data and has no update source.
- **Heuristics stay conservative and opt-in.** `missingHeaders` judges only user agents that claim to be a browser, and expects `Sec-Fetch-*` only from versions that always send them, over secure origins. `ja4Mismatch` (`src/ja4.ts`) flags only clear contradictions: a cipher hash in its small table (from FoxIO's public JA4+ mapping) against a user agent claiming Chromium, Firefox or Safari; an unknown fingerprint, HTTP/3 (`q…`), iOS user agents and Apple's stack behind a Mac user agent (iPad desktop mode) are no decision. Add a hash only from a public source, and only for a stack no real browser with that user agent uses. The Snippet leaves the check out when no site turns it on (`__SID_UNUSED_BOT_JA4__`). Before widening it, think about the real visitors it would misclassify: `SID_SKIP_BOTS=likely` stops their SharedID.
- **Settings fail loudly:** `botSettings` throws on an unknown key or a wrong type; the secret check never echoes the value.
- **Consent doesn't apply to the signal** (a maintainer decision): it runs and reports under GPC, COPPA, opt-out and denied consent. Never store or log anything about the request.
- Tests in `test/ja4.test.ts` cover the JA4 table, the user agent claims, known contradicting and agreeing pairs, and `SID_SKIP_BOTS` with a platform JA4; `conformance/cases/module-bot-ja4.json` checks that without a platform JA4 (every local target) nothing is decided, and that a JA4 header a visitor sends is ignored. Tests in `test/bot.test.ts` cover the settings, the user agent table, the heuristic, the internal cookie and token, consent and `SID_SKIP_BOTS` through `createHandler`, on `/v1` and `/sync`. Conformance cases are in `conformance/cases/module-bot.json`, `conformance/cases/skip-bots.json` and `conformance/cases/skip-bots-sync-modules-none.json`. The runner's HTTP client always sends `Sec-Fetch-Mode`, so cases use an empty `Accept-Language` for the heuristic.
