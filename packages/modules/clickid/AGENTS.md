# packages/modules/clickid

User documentation is in [README.md](README.md) (also the npm package page); keep it in step with behaviour changes. The rules for every module are in [`../AGENTS.md`](../AGENTS.md).

The `clickid` module (`@sharedid-edge/module-clickid`): stores ad click IDs from the landing page's URL (the `url` parameter, else the `Referer`) in server-set first-party cookies, `<unix seconds>.<id>`, for `maxAgeDays` (90) from the click. See the [spec section](../../../spec/modules/clickid.md).

- **Never in the payload.** Click IDs must not reach bidders: no `eids`, no `ortb2`, nothing in `ext`, no headers. The module returns cookies only, so core reports `empty`. Don't add an exposure option without a spec decision.
- **Values are checked, never fixed.** One round of decoding (what `URLSearchParams` does), then `CLICK_ID_PATTERN` (`^[A-Za-z0-9._~-]{1,512}$`); anything else is ignored. The first value of a repeated parameter is the only one considered. Don't decode further, trim or strip characters to make a value fit.
- **The landing URL must be on the request's host or `hosts`, and the request must come from one of them.** A `url` parameter is attacker-chosen, so `landingUrl` also refuses a request with `Sec-Fetch-Site: cross-site`, or with a `Referer` that isn't on those hosts. Together that's what stops another site planting a click ID through a link to the worker; keep the checks exact (no suffix or wildcard matching).
- **The lifetime counts from the click.** The same ID already in the cookie isn't set again (`storedClickId`); a different one replaces it. Don't refresh on later visits.
- **Consent (`clickIdDenial`)** is stricter than the SharedID's: `context.storage`, plus a `us_privacy` opt-out of sale (the parameter, else the `usprivacy` cookie, since `/sync` carries no consent parameters), plus publisher consent for Purposes 1 and 7 whenever there's a TC string or GDPR applies. It's checked in `run`, not declared as `purposes`, because core skips a module with missing purposes before it runs, and on denial this module must delete the click IDs the browser has (`settings.cookies`: enabled parameters and those switched off). `optOutCookies` deletes the same set.
- **`noStore` on every result.** A browser caches `/sync` by URL, the same on every page, so a cached sync would hide later landing pages. Every result carries `noStore: true`, which core honours on `/sync` only. Deployers who don't want uncached syncs leave `clickid` out of `SID_SYNC_MODULES`.
- **Settings are validated strictly** (`clickIdModuleConfig`): unknown keys, wrong types, out-of-range values, duplicate parameters or cookies, and reserved cookie names (`RESERVED_COOKIE_NAMES`: `reflect`'s reserved names plus its keeper `_sid_keep`) throw. The list is written out rather than imported from `@sharedid-edge/module-reflect`, which would bundle all of `reflect` (about 7.7 KB minified) into a Snippet with `clickid`; a test keeps the two in step, so `reflect` is a dev dependency only. Error messages name settings, never configured values.
- **Not yet:** vendor cookie formats (`_gcl_aw`, `_fbc`, `_uetmsclkid`) and per-vendor TCF consent. Both need their own spec change; vendor formats must be checked against current vendor documentation first.
- **Tests:** `test/clickid.test.ts` covers settings validation and reserved names, the URL source and host check, decoding, the pattern and length, repeated parameters, replacement and no refresh, attributes, custom and switched-off parameters, every consent case with deletion, `/optout`, and `/sync` (stored from the `Referer`, `no-store`, cacheable again without `clickid` on `/sync`). Conformance cases are in `conformance/cases/module-clickid.json`.
