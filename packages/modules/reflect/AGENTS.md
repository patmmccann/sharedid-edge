# packages/modules/reflect

User documentation is in [README.md](README.md) (also the npm package page); keep it in step with behaviour changes. The rules for every module are in [`../AGENTS.md`](../AGENTS.md).

The `reflect` module (`@sharedid-edge/module-reflect`): re-sets first-party cookies other scripts wrote (named in `SID_MODULE_CONFIG.reflect.cookies`) with the same value and a new `Max-Age`, so they become server-set cookies. Cookies marked `restore` are also saved in one `HttpOnly` keeper cookie (`_sid_keep` by default) and set again from it when the browser has deleted them. See the [spec section](../../../spec/modules/reflect.md).

- **Values are opaque.** Copy them byte for byte from the raw `Cookie` header (`rawCookieValue`, not `context.cookies`, which strips quotes). Never decode, re-encode, trim, inspect, log or return them, and never put cookie names or values in the payload or in errors. A value that can't be set unchanged (quoted, over 1024 characters, not cookie-octets) is skipped, not fixed. The keeper is the one place values are encoded: it wraps them unchanged (base64url of a JSON object, `encodeKeeper`), and a restored value must come back byte for byte.
- **The one exception to not inspecting values is `prefer: "older"`:** `cookieTimestamp` matches a value against its format's pattern (`TIMESTAMP_PATTERNS`: `ga`, `gcl_au`, `gcl_aw`) to read its creation time, only to choose between the browser's value and the saved one. It never changes either value, never throws, and treats anything that doesn't match exactly (or a time more than a day ahead of the worker's clock) as unparsed, which falls back to `browser`. Ties go to the browser. Keep the patterns strict; add a format only for a documented cookie whose value carries its creation time, with tests for malformed, missing-field, negative and far-future values. The format comes from the exact cookie name (`FORMAT_BY_NAME`) unless `format` is set; `older` without a known format is a settings error, not a silent `browser`.
- **`prefer` is a keeper setting:** `backup` and `older` need `restore: true`. Whichever value wins is set with the cookie's configured attributes and is what the keeper saves. Consent handling is the same in every mode.
- **The keeper is untrusted input.** `decodeKeeper` never throws: anything malformed is empty, and entries are kept only if `isReflectable`. Only configured `restore` names are ever restored from it. It stays within 4096 bytes (name plus value), skipping entries in configured order; don't make it an error.
- **Consent follows `context.storage`,** the SharedID's own storage decision. Don't add separate consent rules here; if the SharedID's rules change, this module follows.
- **Never delete the configured cookies on `/v1` or `/sync`.** They're other parties' cookies (some hold their owner's opt-out state). The one exception is a duplicate with the **same value**: when the request carries several copies, all equal, and the copy being set has a domain, the host-only copy is deleted (`hostOnlyDuplicate`), since no script can see a difference. Copies with different values are never touched. They're deleted only on `/optout`, only for entries with `deleteOnOptOut: true`. The keeper is the worker's own: it's deleted on `/v1` and `/sync` when storage isn't allowed (or there's nothing left to keep), and always on `/optout`.
- **Settings are validated strictly** (`reflectModuleConfig`): unknown keys, wrong types and out-of-range values throw, which makes the module an `error`. Keep error messages free of configured values. `RESERVED_COOKIE_NAMES` lists the names that can't be configured; the keeper's name can't be a configured cookie either; core separately refuses the worker's configured cookie names.
- **No `purposes`:** consent comes from `context.storage`, which already applies TCF. The output is cookies only, so core reports `empty`.
- **`routes: ['v1', 'sync']`:** it runs on Prebid.js's `pixelUrl` calls too, so cookies are refreshed and restored on page views without a `/v1` call. Keep its output cookies-only, since `/sync` has no payload.
- **Tests:** `test/reflect.test.ts` covers settings validation, byte-for-byte reflection, every consent denial, reserved names, attributes, `/optout`, the keeper's encoding, decoding, size limit, restore and deletion, each `prefer` mode and the creation-time parsing, and the module through `createHandler`. Conformance cases are in `conformance/cases/module-reflect.json`, for the keeper `conformance/cases/module-reflect-keeper.json`, and for `prefer` `conformance/cases/module-reflect-prefer.json`.
