# e2e

Browser tests proving SharedID Edge works with **unmodified** Prebid.js, in Chromium, Firefox and WebKit, through Playwright, and in real Safari on macOS, through `safaridriver` ([Real Safari](#real-safari)).

- Separate install (`npm ci` in this folder), so the main workspace doesn't pull in Prebid.js and browsers. It imports the built core (`../packages/core/dist`), so run `npm run build` at the root first.
- `server.ts` serves the test page (`site/public/index.html`), Prebid.js and `/_sid/*` (the core handler) from one origin. It runs with `SID_SYNC_CACHE_SECONDS=0` so every visit reaches the endpoint, and with the `reflect` module (`uid1`, and `_ga` with `restore`), the `clickid` module (default settings) and the opt-in `gpp` module, which run on Prebid.js's `/_sid/sync` calls; it imports the built modules (`../packages/modules/*/dist`). A landing page with `?gclid=…` checks that `clickid` keeps it in a server-set `_sid_gclid` a page script can read, from the pixel call's `Referer`.
- **`pbjs.getUserIdsAsync()` resolves** with `extend: true` and `pixelUrl` since Prebid.js 11.49.0 (prebid/Prebid.js#16135; in 11.48.0 and earlier it never resolved on later visits). A test checks it. Most tests still wait for the `/_sid/sync` response, since that's what they inspect.
- **The Prebid.js the page loads** is a bundle of a typical publisher setup (`prebid-modules.json`: TCF and GPP consent management and `tcfControl`, `storageControl`, `userId` with SharedID and Unified ID, the OpenX, Magnite, TripleLift and Microsoft bidders, `gptPreAuction`, and the generic analytics adapter with its skinny preset), about 100 KB gzipped, not the 4 MB `not-for-prod` build. It shows SharedID works next to them; the page configures only the User ID module. `bundle-prebid.ts` (`npm run bundle-prebid`) assembles it into `site/public/prebid/prebid.js` (gitignored) the way Prebid's download page does: the release's precompiled `dist/chunks` for those modules and their dependencies, checked against its `checksums.json`, between a banner and `processQueue()`. Playwright's local server builds it first; the live workflow builds it before deploying `site/`. Change `prebid-modules.json` to change the setup, then rebuild the TC string (below).
- **`prebid.js` is pinned** to one version in `package.json`, so CI, the live site and local runs all test the same Prebid.js. Dependabot (`.github/dependabot.yml`) proposes the new release weekly; the PR's e2e run checks the `pixelUrl` contract still holds before it merges. If a new Prebid.js release breaks these tests, fix SharedID Edge or report it to Prebid.js.
## Consent: the TC string the tests run with

The page's consent comes from `site/public/tcf.js`, in one of these **scenarios**, picked with `?consent=<name>` in the page URL (`visit(page, '/?consent=denied')`):

| Scenario | Consent | What the tests check |
| --- | --- | --- |
| `given` (default) | GDPR applies; purpose and publisher consent for 1-10 | Every other test runs with it; one checks Prebid.js has GDPR scope and both ID cookies are set |
| `denied` | GDPR applies; no purpose 1 consent for vendors or the publisher | Prebid.js (`tcfControl`) writes no id and doesn't call `pixelUrl`; the endpoint answers `denied: tcf: no publisher consent for purpose 1` and deletes the ID cookies left by an earlier visit |
| `purpose1Only` | GDPR applies; purpose consent for 1-10, but publisher consent for purpose 1 only | Prebid.js (which needs only purpose 1) stores the id and syncs; with `pixelConsent` the endpoint reads the string from `gdpr_consent` and answers `denied: tcf: no publisher consent or legitimate interest for any of purposes 2-10`, even with no `euconsent-v2` cookie or one that allows storage |
| `notApplicable` | GDPR doesn't apply; no TC string | Prebid.js reports `gdprApplies: false`, no `euconsent-v2`, the sync carries `gdpr=0`, and SharedID works as usual |
| `none` | No TCF CMP: Prebid.js gets no TCF consent data | The GPP-only tests, with `?gpp=` |

No CMP runs on the page: static consent data covers what the tests need. `tcf.js` sets `window.SID_E2E_TCF`, which the page passes to Prebid.js as static consent data (`consentManagement: { gdpr: { cmpApi: 'static', consentData: { getTCData: … } } }`), and writes the same string to `euconsent-v2`, as CMPs do; `?tcfCookie=none` leaves the cookie out, as CMPs that keep the string only in local storage do.

**`pixelConsent`.** The page sets `pixelConsent: true` (Prebid.js 11.53.0 and later, prebid/Prebid.js#16233), so `sharedIdSystem` adds the consent Prebid.js has to the `pixelUrl` call, after `id`: `gdpr`, `gdpr_consent`, `us_privacy`, `gpp` and `gpp_sid`, each when it has a value. The endpoint prefers `gdpr_consent` to the `euconsent-v2` cookie. The tests assert the sync's exact query string, and that the endpoint decides with it: with no `euconsent-v2` cookie, and over a cookie that says otherwise. `?pixelConsent=off` leaves it out, as on earlier Prebid.js versions or a page that doesn't set it; then the cookie is how SharedID Edge sees the TC string, and a test checks that path still works.

**GPP.** `site/public/gpp.js` (hand-written; the strings are the conformance cases' in `conformance/cases/module-gpp.json`) sets `window.SID_E2E_GPP` from `?gpp=<name>`, which the page passes to Prebid.js's GPP consent management as static consent data: `usnatNoOptOut` and `usnatOptOut` (US National, section 7, without and with an opt-out of sale) and `tcfEuAndUsnatOptOut` (sections 2 and 7, which Prebid.js sends as `gpp_sid=2,7`). With `?consent=none`, the page is GPP-only. The bundle has no `gppControl_usnat`, so Prebid.js still syncs after an opt-out and the endpoint's `gpp` module decides. The live deployments don't build that module, so the opt-out tests run locally only; the others check the query string live too.

**The `given` string** (GVL v186, TCF policy version 5): `CQt-4cAQt-4cAACABBENC6FgAP_AAAAAACiQIEQCQAKgAZAA4ACAAGgARQF5gMZAgQAAAAAA.IAAA.f_gAAAAAAAAA`

| | |
| --- | --- |
| Purpose consents | 1-10 |
| Publisher consents | 1-10 (SharedID Edge's publisher mode needs purpose 1, and one of 2-10) |
| Legitimate interests, special features, restrictions | none |
| Vendor consents | 21 The Trade Desk (`unifiedIdSystem`), 25 Yahoo (extra), 28 TripleLift (`tripleliftBidAdapter`), 32 Microsoft/Xandr (`msftBidAdapter`), 52 Magnite (`magniteBidAdapter`), 69 OpenX (`openxBidAdapter`), 755 Google (extra), 793 Amazon Ads (extra), 1032 Project Agora (`msftBidAdapter`'s `projectagora` alias) |

The `denied` string is the same without purpose 1 in either purpose or publisher consents: `CQt-4cAQt-4cAACABBENC6FgAH_AAAAAACiQIEQCQAKgAZAA4ACAAGgARQF5gMZAgQAAAAAA.IAAA.b_gAAAAAAAAA`. `purpose1Only` has publisher consent for purpose 1 only: `CQt-4cAQt-4cAACABBENC6FgAP_AAAAAACiQIEQCQAKgAZAA4ACAAGgARQF5gMZAgQAAAAAA.IAAA.cAAAAAAAAAAA`. `tcf.js`'s header lists every scenario, its string and each vendor's reason. Decode the string at https://iabgpp.com to check it.

**The vendor consents follow the bundle.** They're every GVL ID the modules in `prebid-modules.json` declare in `prebid.js`'s own metadata (`node_modules/prebid.js/metadata/modules/<module>.json`, `components[].gvlid`, aliases included), plus `extraVendors` in `tcf-config.json` for vendors with no module in the bundle (Google, Amazon, Yahoo). CI runs `npm run tc-string -- --check` (offline). It fails when the vendors in `tcf.js` or in the string differ from what the modules and `tcf-config.json` add up to, for example after a module is added to the bundle, or a Prebid.js bump changes a module's GVL ID.

**To make a different string:**

1. Change what it consents to: a scenario's `purposeConsents` or `publisherConsents` (or `gdprApplies: false`), add a scenario under `scenarios` in `tcf-config.json` (then use it with `?consent=<name>`), change `extraVendors`, or change the bundle's modules in `prebid-modules.json`.
2. Run `npm run tc-string` in `e2e/`. It fetches the current Global Vendor List, encodes the string with the IAB Tech Lab's `@iabtechlabtcf/core`, decodes it again to check it, and rewrites `site/public/tcf.js`. Don't edit `tcf.js` by hand.
3. Update the strings above to match `tcf.js`'s header.
4. Run the tests locally (`npx playwright test`). The `given` scenario must keep publisher consent for purpose 1 (and one of 2-10), or SharedID Edge sets no ID and most tests fail; put a stricter string in a scenario of its own, as `denied` is.

`tc-string.ts` sets `cmpId` 2 and `cmpVersion` 1: placeholders, since Prebid.js and SharedID Edge don't check them.

- **A stand-in vendor tag,** `site/public/vendor-uid1.js`, writes `uid1` from page script on the highest domain it can (the registrable domain, or the whole hostname under a public suffix such as `cloudfront.net`, found with a test cookie as Prebid.js finds it) with a 7-day lifetime, as an ID vendor's tag would, before Prebid.js (`?vendor=late` runs it 1.5 s later, after Prebid.js's pixel call; `?vendor=none` leaves it out). `uid1` is configured as the reflect README's walkthrough says (`domain`, `httpOnly: false`, `restore: true`), and three tests check the walkthrough: one server-set `uid1` for a year with the vendor's value; a deleted `uid1` restored when the tag runs after the pixel call; and re-minted (the browser's value winning) when it runs before.
- WebKit here doesn't simulate Safari's 7-day cap on script-set cookies; tests simulate a capped cookie by clearing it. Real-world Safari lifetimes are measured on deployments.
- **The tests read requests from the browser,** never from the server: the `sid` fixture records the page's `/_sid/*` requests and the cookies sent with them (`request.allHeaders()`). That keeps every test runnable against a live deployment.
- **The cookie domain.** Prebid.js writes `_pubcid` on the highest domain it can, so the endpoint's `SID_COOKIE_DOMAIN` must match; a test checks there's one `_pubcid`, on the expected domain. Locally the page is `http://e2e.sharedid.test`, reached through `server.ts` as every browser's HTTP proxy (no DNS setup), with `SID_COOKIE_DOMAIN=sharedid.test`; live it's `E2E_COOKIE_DOMAIN` (`sharedid.dev`). Don't go back to 127.0.0.1: Prebid.js's root-domain probe misbehaves on an IP address. Tests add their own cookies with `cookieScope(baseURL)`, on that domain.
- **Cookie domain `auto`** (`tests/cookie-domain-auto.spec.ts`, local only): `server.ts` answers some hostnames with other settings: `auto.sharedid.test` (`SID_COOKIE_DOMAIN=auto`), `fixed.sharedid.test` (a fixed `fixed.sharedid.test`, which isn't where Prebid.js writes `_pubcid`, so the test can tell it from `cookie_domain`), `hostonly.sharedid.test` (`host-only`), and `www.pub-a.test` and `www.pub-b.test`, for which it plays the publisher's CDN and forwards `/_sid/*` to an upstream operator's endpoint (`sid.upstream.test`, trusted-upstream mode, `auto`) with the secret and `X-Forwarded-Host`. The page sets `pixelCookieDomain: true` with `?pixelCookieDomain=1`.
- **Live:** `E2E_BASE_URL=https://e2e.sharedid.dev E2E_COOKIE_DOMAIN=sharedid.dev npx playwright test` runs the same tests against the Cloudflare test zone, with no local server. `site/` is the live test site (a static-assets Worker); the [Live tests workflow](../.github/workflows/e2e-cloudflare.yml) deploys it with the latest Prebid.js copied into `site/public/prebid/` (gitignored). See [Live tests](../packages/adapters/cloudflare/README.md#live-tests). The AWS live tests run them the same way against a CloudFront distribution's `<id>.cloudfront.net` hostname, with `E2E_COOKIE_DOMAIN` set to that hostname, since `cloudfront.net` is a public suffix ([Live tests](../packages/adapters/aws-lambda/README.md#live-tests)); `packages/adapters/aws-lambda/live/deploy.sh` uploads `site/public/` to S3.
- Type-check with `npm run typecheck` (strict, the root `tsconfig.base.json`).
- **CI installs browsers with [`.github/actions/install-browser`](../.github/actions/install-browser/action.yml), which runs `install-browser.sh`,** never `npx playwright install --with-deps` directly: the Ubuntu apt mirrors GitHub's runners use are sometimes unreachable or very slow for hours, and the runner image lacks some of WebKit's packages (`libevent-2.1-7t64`, for one). It installs the browser from Playwright's CDN, then its system packages from `.deb` files cached by runner image (`ImageOS`, `ImageVersion`), browser and `package-lock.json`, with no network. On a cache miss it installs them through apt with time limits, trying another Ubuntu mirror (`archive.ubuntu.com`, or `azure.archive.ubuntu.com` when the runner already uses `archive.ubuntu.com`) when the runner's fails or is too slow, and caches what it downloaded. When apt is unavailable too, it checks the browser's executables with `ldd`: with a library missing, the job fails as an apt outage, naming the libraries, and the live workflows' issue says so; with none missing, it carries on with the image's packages.
- Run one browser with `npx playwright test --project=chromium` (or `firefox`, `webkit`). CI runs each browser as its own job: `e2e-chromium` first, then Firefox and WebKit (the `e2e` matrix) and real Safari (`e2e-safari`, below), which start only once Chromium passes. Each job installs only its own browser.

## The sGTM tests

`sgtm/` runs SharedID Edge beside Google's real server-side GTM image, to check the [variable template](../templates/sgtm/README.md) and what [docs/sgtm.md](../docs/sgtm.md) says about Google's cookies and consent. It's test infrastructure, like the rest of this folder, not a setup for publishers. Everything about it (the stack, the container export, the one-time setup, what the tests check) is in [`sgtm/README.md`](sgtm/README.md).

- Its own Playwright config, `playwright.sgtm.config.ts` (`npm run test:sgtm`), Chromium only; `npx playwright test` doesn't run it. It needs the docker compose stack running, and the stack needs a Tag Manager server container's `CONTAINER_CONFIG`.
- `sgtm/gtm/container.json` is generated by `sgtm/container.ts` (`npm run sgtm-container`) from `templates/sgtm/sharedid-variable.tpl` and `sgtm/gtm/*.tpl`. Don't edit it by hand; CI fails when it's out of date (`npm run sgtm-container -- --check`). After changing it, the container in Tag Manager must be re-imported and published for the tests to see it.
- The page reuses `site/public/tcf.js`, `vendor-uid1.js` and the Prebid.js bundle; nginx serves them from this folder.
- Where Google's documentation is silent, the tests record what they see (`observed:` lines, in the run's summary) and don't assert it. If a test shows a claim in docs/sgtm.md is wrong, fix the doc, not the test.

## Real Safari

Playwright's WebKit isn't Safari: it doesn't apply Safari's privacy rules, and its cookie timing differs. `safari/safari.test.ts` runs the core tests in **real Safari**, through `safaridriver` (WebDriver, with `selenium-webdriver`), on the same page, Prebid.js bundle and consent scenarios: a first visit gets server-set `_pubcid` and `_pubcid_sv`, one of each, on the cookie domain; a cleared script cookie is restored, in the cookie and in Prebid.js on the next page view; `denied` stores nothing and the endpoint deletes what an earlier visit left; with `pixelConsent` and no `euconsent-v2` cookie, the sync carries `gdpr=1` and `gdpr_consent`, and `purpose1Only` makes the endpoint delete the ID cookies; `notApplicable` works.

- **CI:** the `e2e-safari` job in `ci.yml`, on a `macos-latest` runner, for every pull request (no account needed), after `e2e-chromium`. It isn't in the live workflow yet.
- **On a Mac,** after `npm run build` at the root and `npm ci` here:

  ```sh
  sudo safaridriver --enable                                   # once: allow remote automation
  echo "127.0.0.1 e2e.sharedid.test" | sudo tee -a /etc/hosts  # once: Safari can't use the proxy trick below
  npm run test:safari
  ```

  It builds the Prebid.js bundle, starts `server.ts` on port 4310 and browses `http://e2e.sharedid.test:4310` (cookie domain `sharedid.test`). `E2E_BASE_URL=https://e2e.sharedid.dev E2E_COOKIE_DOMAIN=sharedid.dev npm run test:safari` runs it against the live site instead.
- **No network events in WebDriver:** the tests see the page's `/_sid/sync` call through resource timing (`performance.getEntriesByType('resource')`), and cookies, HttpOnly ones included, through WebDriver's cookie commands.
- **A new Safari session per test.** In Safari, WebDriver's `deleteAllCookies()` leaves cookies on the parent domain (`.sharedid.test`), so it can't reset the ID cookies; the tests clear the script cookie from the page, as the Playwright tests use `clearCookies`.
- **The pixel-cookie race.** `sharedIdSystem` reads `document.cookie` in the pixel's load handler. Playwright's WebKit on Linux almost always runs that handler before the pixel response's `Set-Cookie` shows in `document.cookie` (it shows by the next task), so on the page view where the endpoint restores an id, Prebid.js keeps its own new id in memory; on Windows that's rare, and real Safari didn't show it in 30 runs. The Safari and Playwright tests both check the restored id in Prebid.js on the next page view.
