# The sGTM tests

These tests check SharedID Edge's server-side Google Tag Manager (sGTM) integration against **Google's real tagging server image**, the way the rest of `e2e/` checks the Prebid.js integration against unmodified Prebid.js. They cover the [SharedID variable template](../../templates/sgtm/README.md) and what [Using SharedID Edge with server-side GTM](../../docs/sgtm.md) says about Google's cookies and consent.

This is test infrastructure, not a way to run SharedID Edge: SharedID Edge belongs at the edge, on your CDN. The stack here puts both servers on one hostname behind nginx only so the tests can see them together.

## What runs

```text
Chromium (www.sharedid.test → 127.0.0.1) ──► nginx, https://www.sharedid.test:8443 (self-signed)
                                               ├─ /_sid/*     ──► sharedid      SharedID Edge's Node.js server, built from this checkout
                                               ├─ /metrics/*  ──► sgtm          gcr.io/cloud-tagging-10302018/gtm-cloud-image:stable
                                               └─ anything else ──► the test page (site/index.html), and the e2e page's scripts
https://sgtm-preview.sharedid.test:8443 ──► nginx ──► sgtm-preview (the same image, RUN_AS_PREVIEW_SERVER=true)
```

| File | What |
| --- | --- |
| [`docker-compose.yml`](docker-compose.yml) | The stack: `certs` (writes nginx's certificate), `proxy` (nginx), `sharedid`, `sgtm`, `sgtm-preview` |
| [`.env.example`](.env.example) | `CONTAINER_CONFIG`, the hostnames, `SID_COOKIE_DOMAIN`, the port |
| [`Dockerfile`](Dockerfile) | SharedID Edge's Node.js server (`packages/adapters/node`), built from the repository |
| [`nginx/default.conf.template`](nginx/default.conf.template) | `/_sid/` and `/metrics/` as in [docs/sgtm.md's docker-compose example](../../docs/sgtm.md#both-in-containers-with-docker-compose), with TLS |
| [`site/index.html`](site/index.html) | The e2e page's Prebid.js setup, plus the Google tag sending to `/metrics` |
| [`gtm/container.json`](gtm/container.json) | The server container to import into Tag Manager ([below](#the-container-export)), generated by [`container.ts`](container.ts) |
| [`gtm/sid-echo-client.tpl`](gtm/sid-echo-client.tpl), [`gtm/sid-echo-tag.tpl`](gtm/sid-echo-tag.tpl) | The echo client and tag: test fixtures, not for production containers |
| [`sgtm.spec.ts`](sgtm.spec.ts) | The tests; [`../playwright.sgtm.config.ts`](../playwright.sgtm.config.ts) runs them |
| [`wait.sh`](wait.sh) | Waits until the stack answers, the echo included |

SharedID Edge runs as docs/sgtm.md recommends beside sGTM: `SID_COOKIE_DOMAIN=sharedid.test`, `reflect` keeping `uid1` only (none of Google's cookies), and `clickid`. The page's consent comes from the e2e page's `tcf.js` scenarios: `?consent=denied` gives Prebid.js and SharedID Edge the denied TC string and sets Google's Consent Mode to denied, one choice driving both as docs/sgtm.md recommends.

## What the tests check

Eight Playwright tests, in Chromium (what's tested is server-side; the browser engine doesn't change it):

| Test | Checks |
| --- | --- |
| The variable returns the ID from `/_sid/sync` | A page view through Prebid.js's `pixelUrl` sets `_pubcid` and the `HttpOnly` `_pubcid_sv`, and the echo returns that ID |
| The recovery copy wins | With `_pubcid` cleared, or re-minted to another value, the echo returns the `HttpOnly` copy's ID; SharedID Edge restores it on its next call |
| No invalid value | An invalid `_pubcid` gives no ID; a percent-encoded recovery copy is skipped for a valid `_pubcid` |
| GPC | With `Sec-GPC: 1`, the echo returns no ID even while the browser still sends `_pubcid`; SharedID Edge's next call answers `denied: gpc` and deletes the cookies |
| Opt-out | After `/_sid/optout`, no ID; with `_pubcid_optout` present, ID cookies the browser still sends aren't returned |
| The keeper and sGTM | With `reflect` on `uid1` only, the GA4 client (server managed) sets `FPID` and the Conversion Linker sets `FPGCLAW` for a `gclid` landing; `clickid` sets `_sid_gclid`; over more page views no value changes; `/_sid/*` responses set none of Google's cookies and `/metrics/*` responses none of SharedID Edge's |
| Denied consent | TCF and Consent Mode denied: no `_pubcid`, `_pubcid_sv` or `_sid_gclid`, the echo returns no ID, and no `FPGCLAW` |
| GPC beside sGTM | SharedID Edge sets no ID or `_sid_gclid`, and the echo returns no ID |

Where Google's documentation is silent (docs/sgtm.md's "Not confirmed"), the tests don't assert, they record: `FPID`'s and `FPGCLAW`'s `HttpOnly`, domain and lifetime, whether sGTM sets `_ga` from the server, and whether the GA4 client sets `FPID` with Consent Mode denied or with GPC alone. Each is an `observed:` line in the log and a test annotation; CI lists them in the run's summary. If a test shows docs/sgtm.md is wrong, fix the doc.

## One-time setup

The tagging server runs a container published in Tag Manager, so the tests need a Tag Manager account. Once, for the maintainer (or for your own fork):

1. In [Tag Manager](https://tagmanager.google.com), create a container with target platform **Server**. When asked how to provision the tagging server, choose **Manually provision tagging server**, and copy the **Container Config** string it shows (it's also under **Admin > Container Settings**).
2. **Admin > Import Container**: choose [`gtm/container.json`](gtm/container.json), the default workspace, and **Overwrite**. It adds three custom templates (the SharedID variable, the echo client, the echo response tag), the `SharedID` variable, the `SharedID echo` and `GA4` clients, the echo trigger and tag, and a Conversion Linker tag.
3. Check the import: **Templates** lists the three templates, with the permissions their READMEs describe; **Clients** has `SharedID echo` and `GA4`.
4. **Submit > Publish**. The tagging server only runs published versions.
5. Put the config string in `e2e/sgtm/.env` as `CONTAINER_CONFIG` (copy [`.env.example`](.env.example) first), and in the repository secret **`SGTM_CONTAINER_CONFIG`** (Settings > Secrets and variables > Actions), for [CI](#in-ci). It's a credential for the container: keep it out of commits, issues and logs.
6. Optional: under **Admin > Container Settings**, set the server container URL to `https://www.sharedid.test:8443/metrics`, for Preview.

After a change to `gtm/container.json`, import and publish it again; the tagging server picks up the new version within `CONTAINER_REFRESH_SECONDS`.

## Run the tests

With Docker, from the repository root, after `npm ci` in `e2e/`:

```sh
cd e2e/sgtm
cp .env.example .env               # then set CONTAINER_CONFIG
docker compose up -d --build       # the first build installs and compiles the repository: a few minutes
sh wait.sh                         # until /metrics/healthy, /_sid/v1 and /metrics/sid-echo answer
cd .. && npm run test:sgtm         # builds the Prebid.js bundle, then runs the tests
cd sgtm && docker compose down -v
```

The tests reach `www.sharedid.test` without DNS: Chromium maps it to `127.0.0.1`. To look at the page in your own browser, add `127.0.0.1 www.sharedid.test sgtm-preview.sharedid.test` to `/etc/hosts`, open `https://www.sharedid.test:8443/` and accept the certificate warning. `https://www.sharedid.test:8443/metrics/sid-echo` shows what the variable returns for your browser.

The page loads gtag.js from `www.googletagmanager.com` with a placeholder measurement ID (`G-SIDEDGE000`): the container has no GA4 tag, so nothing is sent on to Google Analytics, but the GA4 client claims the events and sets its cookies.

## In CI

[`e2e-sgtm.yml`](../../.github/workflows/e2e-sgtm.yml) runs the tests on an Ubuntu runner after a merge to `main` that changes this folder, `templates/sgtm/` or the workflow, nightly, and on demand. Without the `SGTM_CONTAINER_CONFIG` secret it ends with a notice and tests nothing. A failure after a merge or nightly opens an issue, "sGTM tests are failing", as the live tests do ([`live-issue`](../../.github/actions/live-issue/action.yml)); a later green run closes it. Pull requests never get the secret; their CI checks only that `gtm/container.json` matches the templates (`npm run sgtm-container -- --check`) and that `docker compose config` accepts the compose file. See [How SharedID Edge is verified](../../docs/verification.md#the-sgtm-tests).

## The container export

`gtm/container.json` is in Tag Manager's container export format (`exportFormatVersion` 2): one `containerVersion` with `container` (`usageContext: ["SERVER"]`), `tag`, `trigger`, `variable`, `builtInVariable`, `client` and `customTemplate`. Each custom template is embedded as its `.tpl` file's text in `templateData`, and the items that use one name it `cvt_<containerId>_<templateId>`. The account and container IDs are placeholders, as in any export; Tag Manager assigns its own on import.

- **Generated:** `npm run sgtm-container` (in `e2e/`) writes it from [`templates/sgtm/sharedid-variable.tpl`](../../templates/sgtm/sharedid-variable.tpl) and the two fixtures in `gtm/`, so the container always embeds the template as committed. Don't edit it by hand.
- **The echo:** the `SharedID echo` client claims `GET /metrics/sid-echo` (it reads only the request path) and runs the container with an event named `sid_echo` and no request data. The `SharedID echo response` tag fires on it, with `{{SharedID}}` in its field, and answers `{"sharedid":"<id>"}` or `{"sharedid":null}`, with `Cache-Control: no-store`. A tag writes the response because tags' fields take variables; whether a client's fields do isn't documented. Permissions: the client has `read_request` (path only), `run_container` and `return_response`; the tag has `access_response` for the status, the body and two named headers.
- **The GA4 client** is Google's, with **Server managed** cookies (`FPID`, `domain` `auto`, two years), the setup docs/sgtm.md recommends; the **Conversion Linker** fires on the built-in All Pages trigger. There's no GA4 tag.
- **Checked against:** the format of public server-container exports (Google's own [gps-phoebe](https://github.com/google-marketing-solutions/gps-phoebe) demo container and [gtm-boilerplate](https://github.com/google-marketing-solutions/gtm-boilerplate) server container; Stape's Shopify container templates, which include a custom client template) and public client and tag templates for the permission shapes. It hasn't been imported into Tag Manager yet.

## Troubleshooting

| Symptom | Cause |
| --- | --- |
| `docker compose` says `Set CONTAINER_CONFIG in .env` | `.env` is missing, or `CONTAINER_CONFIG` is empty in it |
| `wait.sh` times out with no JSON from `/metrics/sid-echo` | The tagging server hasn't loaded the container: it isn't published, `CONTAINER_CONFIG` belongs to another container, or the version without the echo client is still live. `docker compose logs sgtm` shows what it loaded |
| `/metrics/sid-echo` answers `{"sharedid":null}` with `_pubcid` set | GPC, the opt-out cookie, or an invalid value: as designed. Otherwise check the request reaches sGTM with its cookies (Preview's **Request** tab) |
| Two `_pubcid` cookies | `SID_COOKIE_DOMAIN` doesn't match where Prebid.js writes it: change it with `SITE_HOST` |
| The page has no Prebid.js | Run `npm run bundle-prebid` in `e2e/` (`npm run test:sgtm` does) |
